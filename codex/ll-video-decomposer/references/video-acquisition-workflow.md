# 视频链接获取工作流

## 固定顺序

1. 识别平台与链接类型。
2. 检查 `yt-dlp`，用 `scripts/download_video.py URL OUTPUT_DIR` 直接下载。
3. 直接下载失败后，根据平台引导用户在 Chrome 中登录、打开目标视频并完整播放，或至少播放几秒到几十秒。
4. 如果当前环境能识别已加载的媒体资源或浏览器缓存，先尝试取得本地媒体。不要承诺缓存一定可用。
5. 浏览器支持页面资源清单时，先列出已观察到的视频资源并尝试导出。若导出失败但已返回带签名的真实媒体 URL，可立即使用该 URL 下载，附带正常浏览器 User-Agent 和来源页 Referer；签名 URL 可能过期，不长期缓存 URL。
6. 如果需要让下载工具读取 Chrome cookie，先让用户完全退出 Chrome，包括后台进程，再运行 `scripts/download_video.py URL OUTPUT_DIR --chrome-cookies`。
7. 仍然失败时，停止重复尝试链接，请用户下载并提供本地 `.mp4`。

## 稳定性与平台策略

- 本地 MP4 最稳定，应作为最终兜底。
- 小红书先直接下载；失败后再走播放、缓存或登录状态流程。
- 抖音标准链接优先让用户登录 Chrome 并播放一段；只给链接的失败率较高。
- 其他平台先直接下载，再依次尝试已播放资源、登录状态和本地 MP4。

## 两个 Chrome 分支

- “当前浏览器或缓存”分支：播放后在环境能力覆盖时尝试，不要求为了读取 cookie 而提前退出 Chrome。
- “cookie 文件”分支：只有下载工具要读取 Chrome 登录状态时才完全退出 Chrome，否则 cookie 文件可能被占用。

## 失败沟通

- 说明失败发生在直接下载、缓存、还是登录状态读取。
- 不要求用户反复更换同一视频的不同链接。
- 用户说“我已经在 Chrome 播放过了，再从缓存试一次”时，直接进入已播放资源分支。
- 缓存和登录状态都不可用时，只给一个明确下一步：提供本地视频或逐字稿。
